Three Claude Code agents, one Django bug, and a checkout nobody touched

2 November 2026 · The Foil maintainers

Coding agents get better results when you let them run things: install packages, run the test suite, try a fix, throw it away, try again. Running three of them on the same problem and keeping the best answer is better still. Two things make that awkward on your own machine:

  • They need their own copy of the repo. Three agents editing one folder overwrite each other. A git worktree or cp -a per agent is slow on a big repo and leaves out untracked files and build state.
  • They run with your permissions. An agent that can run pytest can also read ~/.ssh, your cloud credentials and the API key it was started with, and send them anywhere.

Foil handles both with one command. Here is a real run.

The bug

Django ticket #30257: Django's username validators used the regex ^[\w.@+-]+$. In Python, $ also matches just before a trailing newline, so "alice\n" was accepted as a valid username. We rewound a Django checkout (about 6,000 files) to just before the upstream fix and gave the issue text to three Claude Code sessions (Haiku), at the same time.

The run

foil fanout -n 3 --agent claude --check "python check.py" -- -p "Fix this issue: ..."

foil fanout made three copy-on-write branches of the checkout, started one agent in each under --strict, waited, then ran the check (the upstream fix's own tests, hidden from the agents) inside each branch:

foil: 3 attempts of username in 22.4 s
  attempt      status   check  changes  time
  username-1   0        pass   1        20.7 s
  username-2   0        pass   1        16.5 s
  username-3   0        pass   1        20.8 s
best: username-1

All three agents found the right fix: \A[\w.@+-]+\Z, which is the fix Django shipped. Each one also ran Django's own auth test suite inside its branch first. Until the last step, git status in the real checkout showed nothing. Then:

foil diff --patch username-1     # read the change
foil pick username-1             # apply it; discard username-2 and username-3
applied 1 change; discarded username-2, username-3

What the agents could reach

The same strict sandbox, probed from inside:

API key it sees:  foil-injects-the-real-key
~/.ssh:           ls: cannot access '/home/me/.ssh': No such file or directory
processes:        5 visible
example.com:      urllib.error.URLError: <urlopen error Tunnel connection failed: 403 Forbidden>

Each agent saw the checkout, the Python environment we allowed, an empty home folder and its own processes. It could reach api.anthropic.com and nothing else, and only through foil's proxy, which adds the real API key on the way out. The key inside the sandbox is a placeholder, so a prompt-injected agent has nothing to leak.

Why copy-on-write

A foil branch doesn't copy the repo. It's a layered view of your folder (overlayfs on Linux, APFS clones on macOS), so files are copied only when the agent writes them. On the Django checkout:

A private copy of the 6,000-file checkouttime
cp -a327 ms
git worktree add (tracked files only)490 ms
foil run -b (branch and start)~25 ms

On a 1 GB, 10,000-file workspace, cp -a takes 1.9 s and 977 MB of disk; a foil branch still takes about 25 ms and stores only the files that change. (Linux 7.0, 4-vCPU VM. On an Intel Mac, a first branch of 10,000 files takes 0.65 s and later runs 70 ms.)

Does the sandbox get in the agent's way?

We ran Claude Code (Haiku 4.5) on 31 SWE-bench Lite tasks twice: bare, and under foil agent in strict mode. It solved 17/31 bare and 19/31 under foil, at $9.97 and $10.54. That's within run-to-run noise, so read it as "no worse", not "better". The first foil run found a real bug in foil (paths given through a symlink weren't visible in the sandbox). We fixed it, and that's why the numbers above come from the second run.

What foil isn't

Foil uses your machine's kernel. It protects you from an agent that's wrong or has been misled: one that deletes the wrong folder, reads secrets it shouldn't, or phones home. It doesn't protect against an attacker with a kernel exploit. For code you don't trust at all, use a microVM, or foil vm, which runs foil inside a Lima VM.

Try it

brew install ai-agentic-tools/tap/foil     # or: cargo install foil-sandbox
cd your-repo
foil fanout -n 3 --agent claude --timeout 15m --check "make test" -- -p "fix issue #123"

The Django demo is in examples/django-username (it needs an Anthropic API key). examples/best-of-n runs in five seconds with no API key: four scripted agents, one of which goes rogue and gets nothing.
